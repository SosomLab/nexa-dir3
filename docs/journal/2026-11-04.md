### §1-3 결과 — 교착 사슬(GUI 스레드 18444 · 아래→위)

1. 앱 WndProc(winit `public_window_callback`)이 **`TaskbarCreated`(0xC06E)** 를 받는다.
2. winit `event_loop.rs:2455` `let window_state = userdata.window_state_lock();` → `:2456` `set_skip_taskbar(window, window_state.skip_taskbar)` — **가드를 쥔 채** `explorerframe!TaskbarList::AddTab` → `user32!SendMessageW`(작업 표시줄 창 0x10168)로 **동기 대기**.
3. 대기 중 들어온 테마 변경 후처리: `uxtheme!ThemePostWndProc` → `OnOwpPostThemeChanged` → `CThemeWnd::ChangeTheme` → `SetFrameTheme` → `win32u!NtUserSetWindowPos`.
4. `SetWindowPos`가 같은 창에 **`WM_WINDOWPOSCHANGING`(0x46)** 을 동기 전달 → winit `event_loop.rs:1300` `userdata.window_state_lock()` → 같은 스레드가 이미 쥔 std `Mutex` → `KERNELBASE!WaitOnAddress` → `ntdll!NtWaitForAlertByThreadId` **영구 대기**.
- 앱 프레임 오프셋(0.29.0 = 75ff1ef 빌드): `+0x6a5324`(Mutex 대기) · `+0x66f28f`(WM_WINDOWPOSCHANGING 분기) · `+0x660094`(WndProc 진입 · 2회) · `+0x665c82`(AddTab 호출부) · `+0x66e744`(TaskbarCreated 분기).
- **판정**: winit 0.30.13 상류 결함(자기 잠금 재진입). Cargo.lock `winit 0.30.13` · `crates/nexa-dir/Cargo.toml:47` `winit = "0.30"`. **0.30.0도 같은 판 = 해결되지 않음**. 앱은 `skip_taskbar`를 쓰지 않으므로 AddTab 호출 자체가 앱에 필요 없다.
- **계기(추정 · 미재현)**: RDP 재접속 때 셸이 작업 표시줄을 다시 만들며 `TaskbarCreated`를 브로드캐스트하고, 곧이어 `WM_THEMECHANGED`가 온다. explorer 재시작도 같은 경로. 순서가 맞아야 하므로 확률적.
- **형제 앱**: nexa-sql · nexa-beep · nexa-clip도 Cargo.lock `winit 0.30.13` = 같은 조건에서 멈출 수 있다(nexa-slide · nexa-ui는 winit 없음). nexa-dir2 = 로컬 저장소 없어 미확인(Win32 직접이라 해당 없을 가능성 큼).
- **winit 추가 점검(awk 대략 · 확정 아님)**: WndProc에서 `window_state` 가드를 변수로 쥔 채 재진입 가능 호출을 하는 곳 = TaskbarCreated(2455) · `SetCursor`(2163) · `RedrawWindow(RDW_INTERNALPAINT)`(1295). 뒤 둘은 동기 재진입을 일으키지 않는다. `SendMessage` 대기가 따르는 곳은 TaskbarCreated뿐.
