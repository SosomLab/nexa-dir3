## §50 내장 해시 목록 · 용량 · 성능 분석(T-167 · NEW-038) · 사용자 요건 = 별도 스레드 · 진행 확인 · 한 번에 한 작업

- **사용자 요청**(10-05 · 직접): "CRC, BASE64, SHA 등 자주 쓰는 방식 목록으로 만들고 내장할 때 포함 용량, 성능에 미치는 영향 등 정리" + "원본 파일 용량이 크면 메인 프로세스에 영향 → 별도 진행 여부를 확인할 수 있으면서 별도 스레드로 · 이 경우 다른 파일의 해시 요청 등은 제한".
- **이미 들어 있는 것(조사)**: `sha2` 0.10.9가 Cargo.lock에 있음 — `ed25519-dalek`(라이선스 서명 검증 = SHA-512) · nexa-license `machine-id` 기능(SHA-256)이 끌어옴 → **SHA-256/512 코드는 이미 실행 파일 안**(직접 의존으로 쓰면 추가 용량 ≈ 0 · DR-8 원장엔 "직접 사용" 1줄 기록). CRC32 = zip 헤더 값을 읽기만(`ndir-vfs/archive` · 계산 코드 없음). Base64 = dir3 없음(dir2 `oauth.rs` base64url 20줄 · nexa-license는 base32). 비교 기준 release exe = 5.3 MB(10-03).
- **목록 · 용량 · 성능**(용량 = release 증가분 추정 · 속도 = x86-64 한 코어 대략치 · 실측은 구현 때 `bench`):
  - CRC32(zip/IEEE): 직접 · 표 1 KB(바이트) 또는 8 KB(slicing-by-8) · 0.5 → 2~3 GB/s · 무결성(보안 X).
  - CRC32C · CRC64: 직접 · 1~16 KB · CRC32C는 SSE4.2 명령으로 10 GB/s+ 가능(OS 분기 아님 · CPU 기능 판정).
  - Adler-32: 직접 · 1 KB 미만 · 수 GB/s.
  - MD5: 직접 · 3~5 KB · 0.5~0.7 GB/s · 보안 깨짐(배포처 대조용으로만).
  - SHA-1: 직접 · 3~5 KB · 0.5~1 GB/s(SHA-NI 시 ~2) · 보안 깨짐(대조용).
  - SHA-224/256: **sha2 재사용 ≈ 0 KB** · 0.2~0.4 GB/s · SHA-NI CPU면 1.5~2 GB/s(sha2가 실행 때 자동 선택).
  - SHA-384/512: **sha2 재사용 ≈ 0 KB** · 0.5~0.8 GB/s(64비트에서 SHA-256보다 빠름).
  - SHA3-256/512: 직접 5~10 KB(또는 crate) · 0.3~0.5 GB/s · 수요 낮음 → 후순위.
  - BLAKE2b/s: 직접 5~10 KB · 0.7~1 GB/s · 후순위.
  - BLAKE3: crate 50~150 KB(SIMD 포함) · 멀티 GB/s · DR-8 추가 필요 → 제외 권장.
  - xxHash64/XXH3(비암호): 직접 3~10 KB · 10 GB/s+ · **중복 찾기(NEW-041) 1차 거름용**.
  - Base64(해시 아님 · 인코딩): 직접 1~2 KB · GB/s · 해시 값을 Base64로 표시/복사(SRI `sha256-…` 꼴) · 작은 파일 내용 Base64 복사.
  - 권장 묶음(CRC32 · MD5 · SHA-1 · SHA-256 · SHA-512 · xxHash64 · Base64/16진 표기) 합계 ≈ **20~40 KB = 실행 파일의 1 % 미만** · 새 외부 crate 0.
